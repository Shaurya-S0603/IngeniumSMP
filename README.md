# Ingenium SMP
Minecraft Java 26.3 | Windows-hosted | IngeniumBot | Streamlit

## First-time setup (keep Playit OFF until authentication is tested)
1. Install 64-bit Java 25 (https://adoptium.net/temurin/releases/?version=25), Python 3.12+, and Git. Clone this public source repository.
2. You can run SETUP_WINDOWS.bat for Python dependencies, default settings and import if world.zip is beside it. Alternatively, in PowerShell run `py -m venv .venv` and `.\.venv\Scripts\python.exe -m pip install -r requirements-host.txt`.
3. Place the original Aternos world ZIP outside the repo or next to it and run `.\.venv\Scripts\python.exe setup_host.py import-world world.zip`. Never overwrite the original. The archive contains six datapacks and four existing player saves. Offline UUIDs are preserved. Do not change authentication mode or player-name spelling.
4. Download the Minecraft 26.3 Fabric server launcher from https://fabricmc.net/use/server/ and save as `server/server.jar`. Install EasyAuth for **Fabric 26.3** and its required dependencies from https://modrinth.com/mod/easyauth/versions into `server/mods/`. Read the mod documentation; disable premium auto-login/UUID conversion if needed to preserve offline UUIDs. Confirm configured behavior in a local test. No client gameplay mods are intended.
5. Run `.\.venv\Scripts\python.exe setup_host.py configure` to create safe defaults and a local config.json. Edit config.json: set whitelist to the exact existing Minecraft usernames, configure Discord IDs and public address when available. Leave public_access_verified false initially. Read https://aka.ms/MinecraftEULA then explicitly change server/eula.txt to eula=true.
6. Create a Discord server named Ingenium SMP at https://discord.com/app. Create an application named IngeniumBot at https://discord.com/developers/applications, create its bot, enable Message Content intent, then install it in your server with bot and applications.commands scopes. Grant Manage Channels only if you want /setup_channels; grant View Channels, Send Messages, Read Message History, Embed Links. Do not grant Administrator. Enable Discord developer mode, copy server and your user IDs into config.json. Put the bot token in .env (DISCORD_TOKEN=...), not in GitHub or chat.
7. Run START_WINDOWS.bat. Use /setup_channels as the Discord server owner, or create channels yourself and enter their IDs in config.json. Restart the host after editing config. /start starts Minecraft; when autostart is true the host starts it on launch. /stop stops Minecraft but keeps the bot running. Ctrl+C stops both. Test locally on localhost:25565. Check datapack list, inventories and dimensions. Whitelist is disabled by the host on startup; existing whitelist.json is preserved and no player is automatically made operator.
8. With Playit still OFF, register members securely. The host binds to loopback, so use local clients or the mod's documented administrator pre-registration/registration-code mechanism, if supported in the installed version. Use the interactive local supervisor console for administration. Never run two Java servers on the same world. Do not expose unregistered names to an unrestricted tunnel. Disable shared-IP auto-login/session bypass for tunneled players and verify the actual authentication behavior. Do not expose unregistered names publicly; an attacker could register first. Verify login is mandatory and a second client cannot impersonate a registered player. Test old offline UUIDs and inventories. Set public_access_verified=true only when satisfied, and restart. This flag is an acknowledgement, not a security audit. Never expose RCON or console. Install Playit from https://playit.gg/download and create a Minecraft Java tunnel to 127.0.0.1:25565. Keep the agent running. Update public_address in config.json. Do not enable router port forwarding.
9. Deploy dashboard at https://share.streamlit.io using this repo, main, streamlit_app.py.  In Advanced settings/secrets enter:
   ```toml
   server_address = "YOUR-PLAYIT-ADDRESS:PORT"
   discord_invite = "https://discord.gg/YOUR-INVITE"
   ```
   Share the app with your SMP members using Streamlit's sharing controls. Dashboard polls Minecraft's public status only; it does not expose the admin API or assume sample names are complete. Remote controls are through authorized Discord accounts.
10. Windows Settings > System > Power & battery > Screen and sleep: set plugged-in sleep to Never; screen timeout may be short. Keep the laptop ventilated and connected. Win+L is safe. For reboot recovery, use Task Scheduler at logon with the project directory as Start in and START_WINDOWS.bat as the program; the Playit agent also needs to start. Sleep/hibernation/ shutdown takes both Minecraft and the bot offline.

## Data safety
World, backups, logs, local configuration, authentication files and secrets are excluded from Git. Never commit world.zip or share the bot token. Backups run only after Minecraft is fully stopped. Keep an independent backup on another drive. Keep the Aternos copy until migration tests pass. No Oracle deployment yet. A public tunnel is not an authentication layer.

## Features and limits
Discord /status /ip /players /start /stop /restart /backup /setup_channels; staff checks require the configured Discord guild's actual owner or Administrator permission. Chat relay uses JSON tellraw, suppresses mentions and never forwards login/register commands. Minecraft console output formats need live 26.3 testing. Public dashboard supports status, version, latency, player count, datapack catalogue and connection instructions. No simulated stats. Offline-mode username identity requires independent authentication; whitelist alone is insufficient. Bot and dashboard cannot wake a sleeping laptop. No public console command endpoint; authorized Discord staff can use private slash commands. Backups and crash recovery are local.


## Automatic backups (v1.1)
- By default the host checks once per five minutes after an initial one-minute delay. It takes a verified automatic backup when no successful automatic snapshot has been made in 24 hours.
- If Minecraft is running, two player-count checks 10 seconds apart must both report zero. The supervisor then gracefully stops the server, writes and verifies a ZIP, and restarts Minecraft. A player joining in the small interval before shutdown could still be disconnected. If status is unavailable or players are online, the backup is deferred.
- If Minecraft is deliberately stopped, the backup does not start it. /backup also uses this idle-only behavior.
- Snapshots contain all world dimensions, player data, datapacks, server settings, mods and local authentication files, excluding runtime caches and logs. These archives are sensitive; never publish them. They are in backups/ and excluded from Git.
- The seven latest automatic snapshots are retained. Manual backups are not automatically removed. Failed or incomplete archives are not counted. No guarantee of a backup every calendar day if the host is asleep or never idle.
- Set "automatic_backups": false in local config.json to disable automatic backups. Do not run a separate Java server against the same world while the supervisor is running.
- For restoration, stop the host and Java completely, copy the existing server directory somewhere safe, extract the selected ZIP into a new server directory, and test locally with Playit off. Re-download Fabric/Minecraft runtime caches as needed. Retain your .env and local host config separately.
- Run `python -m unittest discover -s tests` to test the backup module before starting the host.

## Owner/admin console (v1.2)
- Type Minecraft commands directly in the START_WINDOWS.bat window, optionally with a leading slash. Local commands use the same maintenance lock as Discord operations and backups. Use stop to stop Minecraft without triggering crash recovery, :start, :restart, :backup or :status for supervisor controls. Ctrl+C shuts down the host. Do not use nested Minecraft commands to stop the server; use stop directly.
- Discord /console command: sends one Minecraft command; /console_logs lines: returns a bounded recent excerpt (up to 50 lines and 1650 characters). Both require the configured guild's actual owner or Discord Administrator permission, checked at execution time. Responses are ephemeral, not posted to public channels. The same actual owner/admin check protects lifecycle commands. /setup_channels remains owner-only. No log channel is created. Public chat relay and status remain public as configured, not raw console logs.
- Logs are held in memory (last 200 lines) for this purpose. Authentication-looking lines are omitted on a best-effort basis; never enter secrets through Discord commands or share log excerpts publicly. Ephemeral Discord messages are not a guarantee against Discord processing or staff copying them. Full local logs remain on the host. Anyone with access to the Windows account/terminal can use the local console; lock the laptop and restrict OS access. Discord permissions do not control the Windows desktop.
- Discord Administrator is a powerful permission; grant only to fully trusted people. Console commands can change the world and permissions. No in-game operator is automatically assigned, and ops.json is cleared on startup. RCON stays disabled, the server remains loopback-bound, and Streamlit stays read-only. EasyAuth remains required. Verify registered accounts cannot be impersonated before exposing the server.
- The host enforces whitelist off at every start, including after backup/restart. Existing whitelist.json is not overwritten. Anyone who discovers the address can attempt registration, so secure existing names and test authentication.
- After updating, restart the host so Discord slash commands sync. Test both commands with an administrator and a regular member before relying on them. Run python -m unittest discover -s tests with host dependencies installed.
